# Source patterns and boundaries

These sources explain the workflow, not runtime dependencies. Recheck upstream guidance before claiming version-specific compatibility.

## Impeccable

Studied installed Impeccable 4.3.1 SKILL.md and shape, document and new-work guidance on 2026-10-01. [Project](https://impeccable.style/).

Adopt context-first discovery, incumbent visual authority, reusable tokens, separation of product and design facts, progressive disclosure and bounded verification. Omit compulsory workshops, a large command surface and sidecar machinery. This skill writes a small contract; Impeccable can execute the selected brief.

## Matt Pocock's Wayfinder

[Upstream SKILL.md](https://github.com/mattpocock/skills/blob/main/skills/engineering/wayfinder/SKILL.md), inspected 2026-10-01.

Adopt a clear destination, explicit decisions, named open questions and scope boundaries. Store each decision once. Adapt these to a small local note rather than requiring tracker issues, dependent skills, parallel agents or a one-decision-per-session limit.

## DESIGN.md format

[Upstream format](https://github.com/google-labs-code/design.md/blob/main/docs/spec.md), alpha specification inspected 2026-10-01.

Use canonical headings and an optional token layer. Preserve existing schemas; identify the implementation source for extracted values instead of creating competing authorities.

## User requirements

The seven styles and all-six-techniques requirement come from the user's brief. Audience fit in the style library is a hypothesis. Example sites illustrate particular traits; they do not prove popularity, revenue, accessibility or use of all six techniques.

Expanded style profiles on 2026-10-02 are editorial implementation guidance derived from those directions, not measured trend claims or rigid industry standards. Shared accessibility and motion guidance links to primary W3C and web.dev sources in `foundations.md`. Keep normative accessibility criteria distinct from selected project rules and adjustable style defaults.
