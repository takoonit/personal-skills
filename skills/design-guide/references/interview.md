# Comfortable discovery

Start with a short evidence-based reading: “This looks like a booking service for returning customers; quick date comparison seems to be the main job.” Then ask only the unresolved decision most likely to change the result.

Use plain language, concrete choices and one recommendation with its cost. Match the user's language. Behaviour and context usually matter more than demographic detail; do not ask personal questions without a design reason.

## Choose a question, not a questionnaire

| Missing evidence | Useful question |
|---|---|
| Main job | “What should someone do first: understand the offer, compare options, or complete a task?” |
| Situation | “Are visitors exploring for the first time, or returning to get something done quickly?” |
| Identity | “Should this feel quietly precise or bold and playful? I recommend the first because people need to compare detailed information.” |
| Existing brand | “Which part must remain recognisable: colours, typography, or overall composition?” |
| Star/content | “What real material explains the value best: the product itself, an example result, or a customer's story?” |
| Scope conflict | “The brief asks for a new look, while repo guidance pins this brand. Which governs this change?” |

Adapt to actual evidence. Do not paste the table as a form, reconfirm explicit permission, or ask an aesthetic question simply to fulfil a ritual.

## Make choices understandable

Example:

> **Editorial design, recommended:** image-led case studies with clear captions; suits customers evaluating your judgement. Requires more editorial work.
>
> **Intentional minimalism:** direct service comparison; easier to maintain, with more pressure on copy and photography to create character.

Show at most three choices, usually two. Use visual examples when seeing the difference matters. Verify current pages if retrieving sites. Name the particular feature illustrated; do not claim a site uses all six techniques without checking. A gallery listing or award proves neither conversion nor audience preference.

## Stop at sufficiency

Proceed once audience context, task, scope, constraints and selection authority are clear. If the user delegates, choose. If answers are unavailable, mark a provisional assumption. Never fabricate an interview response, confirmation, preference study or usability result.

A colour choice can usually be proposed. An unknown target repo or incompatible scope instruction may block writes. Continue work independent of the unanswered question.
