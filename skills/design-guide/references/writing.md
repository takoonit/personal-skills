# Write the smallest useful contract

## Ownership

Use DESIGN.md as durable visual authority, retaining its incumbent path/spelling. Keep product facts in existing specs and link only what informs design. Keep guardrails beside the design file and reference sections rather than duplicating values.

Merge authorised changes; preserve unrelated text and existing identity unless a redesign was requested. An explicit update request does not need another approval ritual. With no repo, use the environment's normal persistent artifact workflow; do not invent repo configuration.

## Evidence and status

Record primary style, selection provenance, scope and short evidence pointers. Distinguish observed implementation, selected decisions and provisional proposals. “Implemented”, “approved”, “tested” and “popular with” require evidence.

A proposed system may include specific values without pretending they already exist in code. Record missing assets and unresolved choices explicitly. Each six-technique index row needs a concrete decision plus section pointer, not “use good typography”.

For documentation-only work, an absent technique is a finding, not permission to add it. Record its observed absence, preservation decision and concrete advisory proposal in the technique row/section. Keep adoption unresolved and out of binding guardrails until authorised. All six remain addressed; do not misdescribe blank space as an existing depth treatment.

Select three to five binding style rules from the chosen profile and project evidence. Make each observable: rule, affected surface/component, authority or proposed destination, review evidence and any material exception. In incumbent documentation, extract supported rules and keep new profile suggestions advisory. Do not elevate every style default into a project requirement.

Use concrete rules such as “keep campaign supporting copy static; render the full headline in reduced motion”, not “use purposeful animation”. Put these under Overview or link their canonical section. Carry the highest-risk rules into guardrails by specialising the existing bullets; do not append a second long checklist. The six techniques remain mandatory across all styles.

Under Layout, record materially different compositions/treatments, comparison method and selection reason. Use identical content/task and say when comparison was conceptual. In documentation-only work retain the incumbent and mark alternatives advisory.

Resolve responsive reflow, long/localised content, meaningful states and asset failure for the relevant surface. Motion-led designs need a compact motion/beat contract; asset-led designs need source/crop/fallback rules. Store these in the existing Layout/Components sections rather than inventing a parallel document system. Distinguish accessibility requirements from adjustable type, spacing or timing heuristics.

## Tokens and format

Use the eight canonical sections in the template. Optional frontmatter can carry actual tokens with `colors`, `typography`, `rounded`, `spacing` and `components`. Preserve existing tool-owned formats. Keep depth/motion prose in the affected section instead of inventing unsupported token groups.

For existing code, prefer a source map:

| Role | Canonical token/component | Source | Application |
|---|---|---|---|
| Primary action | Actual token name | Actual path | Main committed action |
| Supporting text | Actual token name | Actual path | Explanation on specified surface |

Resolve every observed row to a real source. Store raw values in the canonical location or a clearly identified extracted snapshot; do not maintain independent duplicates. Preserve naming conventions and installed fonts. Compare docs/code conflicts openly instead of choosing the convenient source silently.

For explicit redesign, identify proposed token changes and migration needs without claiming implementation occurred. Do not create Impeccable sidecars/config by imitation. If its document command is used for an authorised extraction, let that workflow own those artifacts; otherwise deliver an independent DESIGN.md.

## Concision

Target 600–1,000 prose words and at most 12 guardrail bullets, about 250 words. These are editing budgets, not excuses to remove essential existing rules. Replace adjectives with inspectable choices: where the motif recurs, which component is reused, how narrow screens behave.

Exclude fabricated claims, extra themes, invented components, unsupported typography licences and compulsory tools. Do not copy the entire seven-style catalogue into a project's contract.
