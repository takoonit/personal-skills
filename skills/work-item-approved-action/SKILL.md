# Work Item approved action

Run inside the [chain](../work-item-delivery/SKILL.md). The runtime card `docs/phases/approved-action.md` is the contract. This is execution, not a new task: no helper tools, refactors, extra tests, reviews, panels, worktrees, design passes or repeated consent.

1. **Record.** If the user's instruction is not yet recorded, record it with `approve-action` (`templates/approved-action.example.json`). An existing publication approval is reused.
2. **Check once.** Refresh the PR identity, source and target, head, blocking threads, required checks and policies, and mergeability, and record them with `check-action` (`templates/action-preflight.example.json`). A preflight stays fresh for five minutes. An unknown or failed read is not an empty result, and no CI run is not a CI pass. When the patch drifted, inspect it and rerun only the affected checks. The target branch advancing alone does not restart review.
3. **Execute.** When the check is clear, execute in the same turn through the authorized forge tool under the returned `expected_head`. For a new UI publication with `attachment:NAME` image destinations, create the authorized PR and upload the approved files, then derive the hosted description with `materializePublicationDescription` from `lib/publication-proof.mjs` before updating it (`docs/proof-of-work.md#ui-publication-projection`). "Publish" means ready for review unless the user asked for Draft. "Approve and merge" means record the vote and complete the merge. Never substitute Draft, a comment or auto-merge, and never modify protected repository policies.
4. **Read back.** Read the result from the forge, not from the command's message (`docs/harnesses.md`). Keep the raw response, and hash the remote attachments by name, bytes and SHA-256. For a merge, confirm Completed, the destination and merged source, and the merge commit on the fetched destination. Record `published` or `action-completed`. After an uncertain write, read the current state before retrying. Save a created PR's identity at once; later publication updates that same PR. Stop any PR babysitter after merge or abandonment.
5. **Stop.** Report a real blocker with its evidence and the minimum unblock condition: a conflict, a blocking finding, a failing or pending required check, an invalidated review, or missing access or permission. Nits, QA SIT, data repair and broader redesign are not blockers unless they are in scope. Before calling clear ticket acceptance ambiguous, apply the scope test in `docs/business-evidence.md`.
