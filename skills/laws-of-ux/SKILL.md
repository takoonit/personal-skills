# Laws of UX

Use behavioral mechanisms to make a design decision clearer. Law names are optional; evidence and a useful correction are essential.

## Scope and evidence

Own a specific behavioral question, an explicit UX-laws audit, or validation of a named principle. For broad styling, branding, copy, design-system work, or an already accepted implementation, use the appropriate specialist instead. `intentional-design` owns task-focused interface composition and expression.

For visual audits, inspect a rendered interface, screenshot, prototype, or recording. Source code alone does not establish visual findings. State the missing evidence and the smallest way to obtain it.

Never trade accessibility, informed choice, truthful state, privacy, or recovery for a business metric. Reject hidden fees, misleading defaults, false urgency, and obstructed exits.

## Diagnose or audit

1. Establish the user, task, context, and relevant constraint.
2. Separate observations from inference. Choose the dominant friction: **Find**, **Understand**, **Decide**, **Act**, **Remember**, **Learn**, **Wait**, **Recover**, or **Finish**.
3. Identify the simplest plausible mechanism. Grade confidence from the evidence in this context.
4. Recommend the smallest correction, check what it could make worse, and name an observable validation or falsification signal.

In **Diagnostic** mode, focus on the specific problem and use only distinct explanations that affect the decision. In **Audit** mode, scan the relevant journey, consider 3–5 evidence-backed candidate laws, and prioritize 1–3 actions. Return fewer candidates or actions whenever evidence warrants; never pad the list.

Return **No law needed** if naming a mechanism adds no value. Return **Insufficient evidence** if plausible explanations cannot be distinguished. Analytics show behavior, not necessarily its cause.

Keep key misuse checks in view: Miller does not set menu limits; 400 ms is not a universal SLA; Fitts does not justify oversized destructive controls; Hick does not justify hiding legitimate choices.

## Finish

State the verdict and decisive evidence. Connect each material finding to its mechanism, contextual confidence, correction, cost or collision, and validation signal. Use a compact form suited to the question.

For an audit, distinguish tentative candidate laws from prioritized actions. Pass accepted behavior and constraints to implementation only when it is authorized. A review does not authorize UI edits.
