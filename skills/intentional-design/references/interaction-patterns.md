# Interaction patterns

Read the relevant section when designing motion, progress, onboarding, or consequential choices. Adapt these patterns to the accepted design system.

## Fit the context

| Context | Useful response |
| --- | --- |
| New or occasional use | Recognizable labels, contextual guidance, safe defaults |
| Frequent repeated work | Shortcuts, retained context, bulk actions |
| Interrupted work | Saved state, resumability, undo |
| Time pressure | Prioritized information and a clear review path |
| Consequential action | Visible consequence, deliberate confirmation, recovery |

Treat these as hypotheses. Analytics show what happened; task observation and user research help explain why.

## Feedback and motion

Routine actions usually need an immediate, honest state change. Show pending work when completion depends on a network or external service. Meaningful progress can justify a progress indicator. Reserve celebration for a real user-valued milestone.

Use motion to reveal relationships, acknowledge action, or preserve spatial continuity. Routine transitions often work around 150–300 ms, but platform conventions, accessibility, and the action determine the right treatment. Keep motion interruptible and preserve clarity with animation disabled.

Choose one coherent signal: a saved value, inserted item, brief highlight, or completion mark. Avoid stacking motion, sound, haptics, and copy around one event. Respect system preferences.

## Progress and gamification

Prefer progress inherent in the work: completion, mastery, regained control, or a reduced backlog. Before adding points, streaks, or rewards, identify the capability or chosen outcome they make visible.

Reject mechanics whose only benefit is anxiety, return frequency, or conversion. Avoid arbitrary loss framing, variable rewards, or artificial incompleteness. Provide natural stopping points.

## Text and orientation

Keep elements that enable action, establish otherwise unclear state or location, or communicate consequential facts. Headings can distinguish datasets or decisions; repeated breadcrumb, title, subtitle, and explanatory text can obscure the task.

Shorten repeated product promises, explanations of familiar controls, generic encouragement, and unsupported reassurance. Preserve error recovery, accessible labels, necessary disclosures, and unfamiliar-domain guidance.

## Consequential choices

Show real cost, scope, timing, and consequence where the decision is made. Keep legitimate decline, cancellation, mute, and deletion paths discoverable. Scarcity or social proof needs current evidence.

Match confirmation to consequence. Routine reversible choices should remain easy; destructive actions may need deliberate review. Never hide a pending or failed result behind celebratory feedback.
